# experiments-failures

This directory stores experiment runs, broken outputs, and failed attempts used during research and development for this project. Its goal is to keep a reproducible record of what was tried, what failed, and why — so we can learn from it and avoid repeating the same mistakes.

Structure

- experiments-failures/
  - README.md (this file)
  - <experiment-name>/
    - input/              # input files or datasets used for this run
    - output/             # outputs generated by the run (may include broken files)
    - logs/               # console logs, training logs, stack traces
    - notes.md            # human-readable notes describing the experiment and what failed
    - metadata.json       # optional structured metadata (date, commit, config, status)

How to add a new failed experiment

1. Create a directory with a short, descriptive name (use hyphens, e.g., `transformer-tuning-2026-07-30`).
2. Add input/, output/, logs/, and notes.md as appropriate.
3. In notes.md include:
   - Date and author
   - Short description of the experiment
   - Steps to reproduce
   - Observed failure or incorrect output
   - Any troubleshooting already tried
4. Optionally add metadata.json with fields: `date`, `author`, `commit_sha`, `config`, `status` (e.g., `failed`), `tags`.

Privacy & Size

- Avoid committing large binary checkpoints. Instead, include a small sample or a pointer to external storage (S3/GDrive) and a short script to reproduce or download the full artifacts.

Why this helps

Keeping failed experiments organized helps future contributors understand what doesn't work, speeds up troubleshooting, and documents limitations and known issues.
